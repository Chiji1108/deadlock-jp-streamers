# Steam紐付けとDeadlockランク

通常の操作はWebの `/admin` から行えます。[管理画面の手順](./admin.md)を参照してください。以下は管理ダッシュボードから操作する場合の補助手順です。

Convexダッシュボードの **Functions** から実行します。管理権限のあるメンバー専用です。Data画面で直接書き換えず、以下の関数を使ってください。

## 登録・変更

`steamLinks:link` を選択し、引数を入力します。

```json
{
  "twitchId": "対象配信者のTwitch ID",
  "steamAccount": "対象のSteamID64または数値ID付きプロフィールURL"
}
```

`twitchId` はサイトの詳細ページ `/streamers/482411607` の数字部分です。本人のSteamアカウントを確認してから登録してください。

`steamAccount` はSteamID64、`[U:1:12345]` 形式、数値account ID、`https://steamcommunity.com/profiles/…` に対応。カスタムURL `/id/…` は非対応です。数字を文字列として入力してください。

同じ配信者に再実行すると紐付けを変更します。別の配信者に登録済みのSteamアカウントは拒否します。

## 解除

`steamLinks:unlink` に `{"twitchId":"対象配信者のTwitch ID"}` を渡します。表示も自動で消えます。

## 更新・表示

登録直後に取得し、以後約1時間ごとに更新します。1分に最大10件ずつ処理するため大量登録時には順番待ちが発生します。未紐付けの配信者にはバッジを表示しません。

取得中、取得不可、ランク認定中を区別します。403・404では以前のランクを非表示にします。一時的なAPIエラー・通信失敗・不正な応答では最終成功時のランクと確認時刻を保持します。失敗理由・試行時刻・連続失敗数を記録し、5分から最大1時間まで間隔を延ばして再試行します。Retry-After がより長い待機時間を指定した場合はそれを優先します。バッジからSteamプロフィールに移動できます。ホバー・キーボードフォーカスで最終確認時刻を表示します。

ランクはDeadlock APIが観測した直近のランクマッチに基づき、ゲーム画面の現在値と一致するとは限りません。期間フィルターには連動しません。

参照: https://api.deadlock-api.com/docs — `/v1/players/{account_id}/rank`、`/v1/assets/ranks`。

## 一覧のランク順

ランクは配信者名の隣の専用列に表示します。見出しクリックで高い順（`sort=rank`）と低い順（`sort=rankAsc`）を切り替えます。Initiate 1が最下位、Eternus 6が最上位です。未登録・取得不可・未確定はどちらの並び順でも末尾になります。

`rankings` にランク順と逆順のキーを持たせ、期間・LIVE絞り込みに対応したインデックスでページングします。Steamの登録・変更・解除、ランク取得、配信集計の再生成で同期します。追加フィールドは既存データと互換性のある任意項目です。

デプロイ後、cron が `rankOrdering:backfill` を毎分実行し、全ランキング行を50件ずつ補完します。各バッチの続きは直ちに予約され、通常は次の分を待たずに進行します。`migrations` に進捗を保存するため、途中で失敗しても次回同じ地点から再開します。補完後は全期間の行を再走査し、Steam側のランクと並び替えキーが一致することを検証します。不一致があれば補完をやり直します。

検証完了まではランク順のクエリは行を返さず、画面は「ランク順を準備しています…」と表示します。配信時間など他の並び替えは利用できます。完了後は自動でランク順が表示されます。cron は完了済みなら進捗1件の確認だけで終了します。

対象環境を確認したうえで `rankOrdering:status` に `{}` を渡すと、`phase`（backfill / verify / ready）、検証件数 `checked`、修正件数 `repaired` を確認できます。開発環境で進行を早める場合は `rankOrdering:backfill` に `{}` を渡して1バッチずつ実行します。手動実行は必須ではありません。

並び替えキーの意味を将来変更する際は `rankOrdering.ts` の移行名を更新してください。スキーマは互換性を保つ追加 → 書き込み更新 → 自動補完・検証 → 読み取り有効化の順にします。検証後も通常の登録・解除・ランク取得・配信集計は共通の `rankOrder` を使って同一トランザクション内で同期します。
